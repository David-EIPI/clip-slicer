\chapter{Interface Manual}
\label{interface-manual}

\section{Document Window}
\label{document-window}

Each document contains a model list, a toolbar, and an OpenGL viewing area.
The document window is the normal workspace for one or more loaded models.
Use the \hyperref[model-list]{model list} to select models and control their
visibility, the \hyperref[document-toolbar]{toolbar} or
\hyperref[document-menus]{menus} to start operations, and the viewport to
inspect or transform geometry. Detailed gesture descriptions are collected
under \hyperref[mouse-actions]{Mouse Actions}; keyboard access is summarized
under \hyperref[keyboard-shortcuts]{Keyboard Shortcuts}. The close button at
the right edge of the document tab row closes this document.
On Windows, documents retain
the native MDI window controls supplied by the operating system.

Open and export file dialogs retain the directory of the last accepted file
for use by subsequent dialogs. STL and CLI files may also be dragged from the
operating system file manager. Dropping files on the active document content,
including its viewport, section controls, or model list, appends them to that
document. Dropping files on a common application area, including the parent
frame, status bar, empty document-tab area, or document toolbar, creates one
new document containing all dropped files.

The model viewport requires OpenGL 3.2 and GLSL 1.50. If renderer
initialization fails, the application reports the detected OpenGL environment and a sample of missing entry points to assist driver
diagnosis.

\subsection{Model List}
\label{model-list}

The model pane controls selection, visibility, type identification, and
organization. The \emph{Visible} check boxes show or hide geometry without
deleting it. Surface models use a cube icon and normal text; generated slice
models use a stacked-layer icon and italic text. A group name includes its
current model count in parentheses. Commands and transformations apply to all
selected entries.

Models can be placed in named, collapsible groups. Selecting a group selects
all of its children for subsequent commands, and changing a group's visibility
changes every child. Use \emph{Models > New Group} to place the current
selection in a named group and \emph{Ungroup selected} to remove selected
models from their groups. Drag selected rows onto a group to move them into it,
onto another model to adopt that model's group and position, or onto the empty
pane background to ungroup them. Multiple selection uses the platform's normal
Ctrl and Shift conventions. Right-click a model or group to open a context
menu with grouping, arrangement, transformation, slicing, export, and deletion
commands. The Export submenu selects either CLI slices or STL surface geometry.

\section{Menu Commands}
\label{document-menus}

The \emph{File} menu opens one or more models in a new document or in the
active document,
exports selected slices as CLI, exports selected surface models as STL, opens
Settings, and closes the document or application. On GTK, the close button at
the right end of the document tab row closes the active tab; platforms with
native MDI child controls retain their document-window close buttons.
\hypertarget{open-model-dialog}{}The \emph{Open} command uses the Open Model
dialog and creates one new document containing all selected STL and CLI files.
\hypertarget{open-into-document-dialog}{}The \emph{Open into document}
dialog adds all chosen STL and CLI files to the active document.
\hypertarget{export-slices-dialog}{}The \emph{Export Slices} dialog writes the
selected sliced models to a CLI file.
\hypertarget{export-stl-dialog}{}The \emph{Export STL} dialog writes selected
surface models to a binary STL file.

The \emph{Models} menu contains commands that act on every selected model.
\emph{Delete selected} removes all selected models from the current document.
\emph{Reset transformations} restores each selected model's original position,
orientation, and scale. \emph{Transform} combines exact rotation, translation,
and uniform scaling in one dialog. Rotation uses a chosen global X, Y, or Z
axis; rotation and scaling act on the selected models as a group around their
common geometric center, followed by signed translation along the three global
axes. These operations update transformation matrices without changing source
model coordinates. \emph{Move to Origin} preserves the relative placement of
all selected models while translating their combined bounding box so that its
minimum X, Y, and Z coordinates are all zero. The selected group therefore
fits tightly in the positive octant and rests on the build plane.

\subsection{Facet Placement}

The \emph{Place facet on platform} command operates on the first selected
non-sliced surface model. Each nondegenerate triangle receives a geometric
normal and area. Edge-connected triangles are first collected into planar
patches, provided every pair of normals satisfies the configured flatness
tolerance. A second pass merges disconnected patches when their normals meet
the same rule and all their vertices lie inside one plane-normal projection
band. The band width equals the current slicing thickness, so inscriptions,
cutouts, and other interruptions do not split one practical print facet into
several choices. Parallel surfaces farther apart than that thickness remain
separate. Opposite triangle winding is normalized within a facet, preventing
an otherwise flat surface from being split by inconsistent STL orientation.

Before the more expensive disconnected-patch merge, the detector selects actual
model vertices which are extreme along thirteen distributed directions. A patch
is discarded early only when these witness vertices prove that model geometry
lies on both sides of its plane, using a conservative margin for the configured
normal and coplanar tolerances. This inexpensive test cannot reject a patch
because of an empty bounding-box corner.

After merging, a candidate is retained only when a plane parallel to the facet
can support every model vertex from one side. This final exact test rejects
internal and concave surfaces and also determines which normal direction points
away from the model. Candidates
are sorted by decreasing area; surfaces smaller than one percent of the largest
outer facet are discarded, and at most ten remain. When several facets remain,
a dialog lists their areas for selection.

The chosen outward normal is rotated to the negative Z direction about the
model bounding-box center. A final Z translation places the rotated model
minimum on the global Z=0 print platform. As with other model operations, only
the transformation matrix changes; source vertices remain unmodified.

\emph{New Group} organizes the selected models under a named, collapsible row;
\emph{Ungroup selected} returns them to the top level.

\hypertarget{transform-dialog}{}The \emph{Transform} dialog provides numeric
rotation axis and angle, translation, and uniform scale controls. It is a
modeless tool window that remains above its document while allowing continued
selection and viewport interaction. \emph{Apply} transforms the models selected
at that moment and leaves the window open; \emph{Close} hides it. Reopening the
window preserves its control values.

The \emph{Align}, \emph{Distribute}, and \emph{Multiply} commands share the \emph{Arrange selected
models} dialog. The invoking command initially selects its corresponding tab,
but the tab active when \emph{Apply} is pressed determines which operation is
performed on the models selected at that moment. This modeless tool window
remains above its document while allowing selection and viewport interaction.
\emph{Apply} leaves it open and \emph{Close} hides it. Control values on all
three tabs remain available when the window is reopened; the first alignment
defaults to Z and Min.

\hypertarget{align-dialog}{}The \emph{Align} command is enabled when at least two
models are selected. Choose a global X, Y, or Z axis and a Min, Center, or Max
alignment. Min makes every selected model bounding-box minimum on
that axis equal to the selection's shared minimum; Max similarly uses the
shared maximum; Center places every bounding-box center at the center of the
shared bounds. Alignment changes only the chosen coordinate and preserves each
model's rotation, scale, and placement on the other two axes.

\hypertarget{distribute-dialog}{}The \emph{Distribute} tab places the selected
models into cells in their current model-list order. Cell counts are specified
separately for X, Y, and Z. A count of zero makes that axis inactive: model
coordinates on it remain unchanged and its distance-interpretation selector is
disabled. A count of one remains an active single plane and aligns model
centers on that axis. The product of the nonzero counts must be at least the
number of selected models. The fill-order control lists the fastest-changing
axis first and skips inactive axes, so, for example, X then Y then Z fills an X
row before advancing Y and finally Z. Unused cells at the end of the lattice
are permitted. The center of the first selected model remains fixed at the
first cell. On first use, unused cell-count axes default to zero.

Each axis has an independent distance interpretation. \emph{Center distance}
uses a regular lattice step between neighboring cell centers.
\emph{Bounding-box gap} instead guarantees the requested minimum separation
between the bounding boxes in neighboring index planes. For this mode, each
plane is sized from the largest model assigned to that index, and successive
plane centers are separated by half of each neighboring plane width plus the
requested gap. A large part therefore expands only the rows or columns sharing
its index; smaller parts can have a larger gap where they share a plane with
the limiting part. On first use, distance values are initialized to the largest
individual selected-model dimension on each axis.

\hypertarget{multiply-dialog}{}The \emph{Multiply} tab creates a rectangular
array of every selected model. It has a copy count and stride for each global
axis. A count of one leaves that axis unchanged; larger
counts place instances at successive stride offsets. On first use, the stride
values are the X, Y, and Z dimensions of the selected models' shared bounding
box, so
the default array places adjacent copies without overlap. The original models
form the first array position and are included in the requested counts. Replica
geometry is shared in memory, while each instance has its own transformation
and can subsequently be moved or rotated independently. The original models
and all new instances are placed in one automatically named, expanded group.

The \emph{Slice} menu contains commands for regular slicing, interactive
cross-sections, unsupported-area detection, orientation optimization, and
support generation. The \emph{Help} menu's \emph{Topics} command opens the top
of this manual.

\subsection{Slice Dialog}
\label{slice-dialog}

The \emph{Slice selected} command opens this dialog before converting every
selected surface model into layer contours. Slicing uses the layer thickness,
first-layer offset, segmentation tolerance, and contour-healing threshold from
the Slicing tab of Settings.

\subsubsection{Output}
\label{slice-output}

\emph{Same document} adds the generated slice models beside their source
models in the active document. \emph{New document} creates another document
window and places the generated slice models there. Neither choice deletes or
modifies the source surface models.

\section{Toolbar Buttons}
\label{document-toolbar}

The toolbar provides frequently used menu commands. \emph{Hide},
\emph{Show}, and \emph{Delete} affect selected list entries. \emph{Section}
opens the interactive cross-section view, \emph{Supports} generates support
structures, and \emph{Stop} cancels a running background workflow.
\emph{Arrange} opens the shared arrangement dialog at its last selected tab.
\emph{Transform} and \emph{Origin} change selected-model transformations.
Buttons which cannot operate on the current selection are disabled. Files
dropped on this toolbar open together in a new document; drop them on the
viewport or model list to append them to the active document.

\section{Viewport Guides}
\label{viewport}

\subsection{Build Platform}

The rectangle below the models represents the printer build platform. Its
width and length follow the combined transformed bounds of all visible models.
Its upper surface lies on the global Z=0 plane.
The upper surface is dark gray. The underside remains visible when viewed from
below and is shown in silver gray, making the platform orientation apparent.
The first section of the application status bar reports the current build
volume as width, length, and height.

\subsection{Coordinate Axes}

The three thin lines crossing the viewport are the global X, Y, and Z axes.
They pass through the global origin and extend in both positive and negative
directions until clipped by the view. Cross-shaped tick marks remain visible
from different viewing directions. Tick spacing changes with zoom and always
uses a power of ten, such as 0.1, 1, 10, or 100 model units.

The axes belong to the global coordinate system. Camera movement changes their
screen projection, while model transformations move models relative to them.

\subsection{Orientation Vane}

The orientation vane is the group of three thick arrows in the lower-left
corner of the viewport. Its X arrow is blue, its Y arrow is red, and its Z
arrow is bright green. Black X, Y, and Z labels identify the corresponding
arrow ends. The vane rotates with the camera to show the current view
direction, but its screen position and size remain fixed so that it is always
legible.

\subsection{Cross-section}
\label{section-dialog}

The \emph{Section} toolbar button or \emph{Slice > Section} menu command opens
a dialog which configures the interactive section before it is displayed.

\subsubsection{Section plane normal}
\label{section-axis}

The X, Y, and Z choices select the global axis perpendicular to the moving
section plane. The translucent plane spans the shared bounds of all selected
models in the other two dimensions. Z is selected by default because it
previews the horizontal layers produced by normal model slicing.

\subsubsection{Clipping}
\label{section-clipping}

\emph{No} leaves all selected model geometry visible. \emph{Above} hides the
part whose coordinate on the selected axis is greater than the section-plane
coordinate. \emph{Below} hides the part with the lower coordinate. Clipping
changes only viewport rendering; it does not modify models or exported data.

\subsubsection{Auto rotate for best view}
\label{section-auto-rotate}

When selected, this option points the camera squarely at the projection plane
from the side opposite the models and zooms so the plane fits without clipping.
For a Z-normal section, global X is horizontal and global Y is vertical. For
X- and Y-normal sections, Z occupies one screen direction and the remaining
horizontal model axis occupies the other. Clearing the option preserves the
current camera orientation and scale.

\subsubsection{Section position controls}
\label{section-controls}

The section plane can be moved along its normal with Alt+wheel. Plane positions
follow the configured slicing sequence: the first
position for the Z axis is aligned to the global build-layer grid defined by
the first-layer offset and layer thickness. X- and Y-axis sections start at
the selected-bounds minimum plus the first-layer offset. Each subsequent
position advances by one layer thickness. While Section mode is
active, a horizontal scrollbar above the view and a spin box to its right show
and control the slice index. Moving the thumb right increases the index, and
the projected cross-section updates continuously while the thumb is dragged.
With the scrollbar focused, the Up and Down keys move by one slice
and Page Up and Page Down move by ten slices.
The scrollbar and spin control share the exact slice-index limits used by the
plane.

Moving the plane recalculates the intersection contours for selected models.
A filled, double-sided copy of those contours is drawn on a dedicated
semi-transparent plane outside the selected models, and the second status-bar
field reports the coordinate using the selected axis letter. Best-view
alignment faces the display plane squarely and scales it to fit the viewport.
Hiding models affects their rendered geometry only: the build platform,
section and projection planes, and projected contours remain visible, including
when all models are hidden.

\subsection{Unsupported Areas}

The \emph{Detect} toolbar button or \emph{Slice > Detect unsupported areas}
command analyzes the selected models in their transformed positions. The
adjacent \emph{Generate} button and \emph{Slice > Generate supports} command
are the entry point for creating support structures.
The analysis uses the configured slicing thickness, critical support angle,
and overhang coefficient. It runs in the background so that document viewing
remains responsive.

Support generation snapshots the selected transformed models, slices them,
and detects unsupported areas on a background coordinator thread. Its complete
processing sequence is described in Chapter~\ref{chap:generate}.

When analysis finishes, unsupported portions of layer surfaces are overlaid in
bright red-orange. For clearer visibility against the source mesh, each
unsupported area is drawn at the Z position of the preceding layer rather
than the slicing plane on which it was detected. The first layer is treated
as fully supported. The layer-to-layer support test and the treatment of
disconnected islands are described in Chapter~\ref{chap:detect}. Transforming
a model clears the overlay because the previous result no longer represents
its current position.

\subsection{Orientation Optimization}

The \emph{Optimize} toolbar button or \emph{Slice > Optimize orientation}
command searches for orientations which reduce the total unsupported area of
the selected models. Selected models are optimized independently and in list
order. Improved orientations are applied to the document as they are found;
the source vertex coordinates remain unchanged.

The search procedure and its unsupported-area score are described in
Chapter~\ref{chap:optimize}. Several attempts run concurrently. The third
status-bar field reports
completed attempts and the best unsupported-area score for the current model
in the form \texttt{Run 1 of 10 (S=12.34)}. The current orientation is analyzed
first, and its initial score is displayed before rotated search candidates are
evaluated. Model transformations or analysis-setting changes cancel stale
optimization work.
During support generation, the same status field follows an ordered step list:
\emph{Slicing}, \emph{Finding unsupported}, \emph{Contact points},
\emph{Volume segmentation}, and \emph{Generating supports}. Contact discovery
and volume segmentation may run concurrently, but the display advances only
after the last worker for the current step has finished. Contact stages show
calculated or processed contacts in the form \texttt{(10 of 1234)}. Before the
final contact count is known, the total is estimated from unsupported area and
the configured contact spacing.
After generation, contacts for which neither an external nor internal support
could be placed are summarized in the same field. The message includes the
number of failures and the Z coordinate of the lowest failed upper contact.
The \emph{Stop} toolbar button requests cooperative cancellation. Detection,
optimization, and support-generation workers stop between slicing, analysis,
or generation operations, and the controls return to their idle state after
all workers have exited. Interactive Section previews are calculated directly
for immediate feedback and do not enable the Stop button.

\subsection{STL Export}

The \emph{File > Export STL} command writes all selected surface models into
one binary STL file. Stored model transformations are applied to every vertex
and normal. Sliced models are omitted because their visualization mesh is not
treated as source STL geometry. Intersecting input meshes are written without
performing a geometric union.

\section{Settings}
\label{settings-dialog}

The \emph{File > Settings} command opens the application settings dialog.
Settings are grouped into tabs so that additional categories can be added as
the application grows.

\subsection{Slicing Tab}
\label{settings-slicing}

The Slicing tab defines the common contour-generation rules used by ordinary
slicing, unsupported-area detection, orientation optimization, support
generation, and interactive sections.

\paragraph{Layer thickness.}
This is the distance between consecutive slice planes and defaults to 0.1 model
units. A smaller value produces more layers and captures finer vertical detail,
but increases slicing and analysis time.

\paragraph{First-layer offset.}
This is the absolute height of the first Z slice above the global build plane
and defaults to 0.05 model units. Together with layer thickness it defines the
Z sequence \(Z_0 + n dZ\). X- and Y-normal interactive sections use the same
offset relative to the minimum selected-model coordinate on their chosen axis.

\paragraph{Contour healing threshold.}
After initial
segment connection, endpoints separated by no more than this distance can be
joined to close a contour. The default is 0.01 model units. The setting is
used by normal slicing, interactive cross-sections, and unsupported-area analysis.

\paragraph{Segmentation tolerance.}
The segmentation tolerance controls endpoint matching during initial slice
segment connection. Its default is 0.01 model units. It is shared by the
same slicing workflows. It should remain small relative to real model features;
an excessive value can merge endpoints which should remain separate.

\subsection{Analysis Tab}
\label{settings-analysis}

The Analysis tab controls facet detection, unsupported-area detection, and the
randomized orientation search which repeatedly invokes unsupported analysis.

\paragraph{Critical angle.}
This is the smallest supported surface angle above the build plane and defaults
to 30 degrees. Increasing it classifies more shallow surfaces as unsupported.

\paragraph{Overhang coefficient.}
This value defaults to 1 and scales the direct layer-to-layer allowance. For a
layer separation \(dZ\),
the support search radius is
\(dZ (c + 1 / \tan(\alpha))\), where \(c\) is the overhang coefficient and
\(\alpha\) is the critical angle. Increasing the coefficient permits more
horizontal displacement between successive layers before an area is marked
unsupported.

\paragraph{Facet flatness tolerance.}
This dimensionless value defaults to 0.001 and is interpreted as
\(1 - |\cos(\alpha)|\), where \(\alpha\) is the angle between
two edge-connected triangle normals. Smaller values require more nearly
parallel triangles. The absolute cosine allows the facet detector to tolerate
reversed winding while the later supporting-plane test establishes the outward
direction.
\paragraph{Optimization attempts.}
This is the number of independent randomized local searches performed for each
selected model and defaults to 10. More attempts improve coverage of the
orientation space at the cost of additional work.

\paragraph{Worker threads.}
This limits optimization attempts evaluated concurrently and also sizes the
support-generation worker pool. It defaults to 4. Values above the number of
available processor cores usually provide little benefit.

\paragraph{Convergence tolerance.}
This is the minimum unsupported-area reduction accepted as an improving
optimization step and defaults to 0.1 square model units. Smaller values will
result in slower convergence.

When unsupported-area detection takes longer than one second, the status bar
reports the completed slice and total slice count. The report is updated at
most once per second to avoid slowing the analysis with GUI traffic.


\subsection{Generator Tab}
\label{settings-generator}

The Generator tab controls contact sampling and the dimensions and routing of
generated support geometry.

\paragraph{Support spacing.}
This sets the nearest-neighbor distance of the hexagonal contact-point lattice
and defaults to 2.0 model units. Boundary contacts use the same value as their
maximum spacing and search radius.

\paragraph{Circumference points.}
This controls the polygonal resolution shared by circular tip, pillar, and base
surfaces and defaults to 12. Higher values make those surfaces smoother while
increasing generated triangle counts.

\paragraph{Contact tip dimensions.}
The Contact tip group defines the truncated cones placed at detected contact
points. Top radius defaults to 0.25, bottom radius to 0.75, and height to 2.0
model units.

\paragraph{Lattice cell size.}
This controls the spatial resolution of the external-support route search and
defaults to 0.5 model units. Smaller cells permit finer routes but require more
memory and search time.

\paragraph{Model isolation.}
This adds clearance between every external support and the model surface and
defaults to 1.0 model unit.

\paragraph{Minimum support angle.}
This is the smallest permitted angle between an external pillar centerline
segment and the build platform and defaults to 30 degrees.

\paragraph{Base dimensions.}
The cylindrical platform base defaults to a height of 0.5 and radius of 2.0
model units.

\paragraph{Pillar radii.}
The tapered pillar wire defaults to a bottom radius of 0.75 and a top radius of
0.5 model units.
External pillar bases use the global Z=0 build platform. Models intended for
support generation should therefore be placed in the positive Z half-space;
the \emph{Move to Origin} command performs this placement when appropriate.

The Generator settings control contact placement, tip construction, collision
clearance, route resolution, and surface tessellation. Their use throughout
the support pipeline is described in Chapter~\ref{chap:generate}.

\subsection{Interface Tab}
\label{settings-interface}

The Interface tab contains display behavior which does not alter generated
geometry.

\paragraph{Cross-section display distance.}
This controls the gap between the selected-model bounding box and the dedicated
cross-section projection plane. Increasing it separates the projection more
clearly from large models; decreasing it keeps both model and projection closer
together when auto-rotation is disabled.

Settings persist between runs in \texttt{clip-slicer/settings.ini} beneath the
operating system's user configuration directory.
